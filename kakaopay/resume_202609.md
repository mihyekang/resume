## 핵심 역량

### 1. 프로덕트 출시 프로세스 개선 및 운영

- 90여 종 규모 Azure 이관 중 전사 가이드가 적용되지 않는 비표준 6종을 리드하며, 현행 구조·부하 특성·검증 기준·운영 체계·데이터 이관·승인 절차를 포괄하는 16개 항목 질문지를 직접 설계해 이관 절차 자체를 표준화
- 테스트 시나리오 부재를 문서 미비가 아니라 성공 기준의 부재로 분류하고 착수 단계에서 작성을 요청하는 방식으로, 착수 시점 검증 기준 확보를 프로세스에 편입
- 17개 외부 협조사가 스스로 산출물을 제출할 수 있도록 작성 가이드·양식·예시·명명 규칙·기한을 하나의 패키지로 설계·배포해 온보딩 프로세스를 운영 체계로 전환
- 전사 ITO TF에서 3년치 현업 문제 사례를 수집·분류·패턴화해 개별 이슈를 전사 대가산정 프로세스로 정착

### 2. 프로젝트 목표·범위·일정·성과지표 관리

- KT ADD 프로젝트에서 블로커 체류일, 의사결정 리드타임, 마감 명시율 세 지표를 착수 시점에 직접 설계해 주간 추적 ("진행 중"이라는 상태 보고로는 리스크가 드러나지 않는다는 판단)
- Confluence 진척 추적표를 기록이 아닌 관리 지표로 전환해 Pod별 Manifest 진행률을 99.8%까지 추적
- 연동 목록 20% 미완료가 베이스라인 성립 자체를 막는 리스크임을 식별하고 후속 작업의 선후행을 재조정
- 자원 제약(GPU 미확보) 상황에서 전체 범위 대신 SPOTV 1개 채널을 1차 베이스라인으로 재정의하고 차수별 확장 계획으로 범위를 재설계

### 3. 이해관계자 요구사항 조율 및 병목 해결

- GPU 미가용의 원인이 기술적 한계가 아니라 사업부서의 예산 미확보와 물리 장비 부족임을 구분해 PO의 의사결정 사항으로 문서화하고, 범위·일정·리소스 트레이드오프에 오너십과 응답 기한을 붙여 반환
- Azure 이관에서 다른 파트가 Entra ID SSO(Node.js) 구축에 막혀 지연되자, 같은 문제를 먼저 해결한 팀원을 파악해 직접 연결
- Manifest 작성이 핵심 지연 구간이 되었을 때 인력 투입을 기다리지 않고 Kubernetes를 직접 학습해 작성과 환경 설정에 참여, 그 과정에서 CKA 취득
- 협력사 확인이 필요한 사안에는 즉시 잠정 답변 후 확정일자 후속 회신을 보내는 2단계 응답 구조를 도입해 무응답 구간 제거

### 4. 일정·마일스톤·이슈·리스크 관리

- KT ADD에서 단위테스트 포함 1차 개발완료, 전체 개발완료, 연동테스트 및 임원보고, 검증, 전체 배포로 이어지는 마일스톤 체계 수립
- 배포 대상이 3배로 늘고 서버 생성이 3주 지연되는 상황에서, 일정 만회 대신 Scale-out 가능한 구조 확보를 우선 판단해 요구사항 개발과 배포 스크립트를 병렬화
- 대외는 대화형, 내부는 결정 및 리스크 레지스터·NFR 로그로 이원화해 운영하는 이중 트랙 커뮤니케이션 체계 설계
- 회의 후 요약 회신 메일을 의사결정 로그로 활용하고, 별도 협업툴이 없는 구간은 이메일 스레드를 공식 기록 체계로 전환

### 5. 애자일 및 협업툴 운영·전파

- KT BIT Order Interface 개발(2013~2014)에서 Agile Sprint 방식으로 오더-Legacy 연동 인터페이스 약 50~60종 개발에 참여
- Jira·Confluence를 프로젝트 표준 협업툴로 운영, Confluence 정보구조를 상위·중위 6개 섹션의 얕은 계층으로 재설계해 문서가 많아도 찾을 수 없어 안 읽히는 문제를 해소
- 확정되지 않은 이해관계자 의견이 요구사항이나 리스크로 오인되지 않도록 트래킹 기준을 별도 운영해 협업툴 내 정보 신뢰도 유지

## 대표 경험

### 1. 이관 조건 자체가 없는 영역에서 프로세스를 설계하고 온타임 완료

**KT Azure Mass Migration · Non-ITO PL · 2025.01~2025.12**

90여 종 이관 대상 중 전사 가이드가 적용되지 않는 비표준 6종을 맡았습니다. 표준 대상은 정해진 절차를 따르면 되지만, 담당 영역은 이관 조건 자체가 정의돼 있지 않았습니다. 현행 구조·부하 특성·검증 기준·운영 체계·데이터 이관·승인 절차를 포괄하는 16개 항목 질문지를 직접 설계해 6종 전체에 동일 적용, 비교 가능한 형태로 수집했습니다. 이 과정에서 테스트 시나리오 부재를 성공 기준의 부재로 분류해 착수 단계 작성을 요청했고, 방화벽 필요 항목을 사전 정리해 이관 시점의 대기 구간을 없앴습니다.

배포 대상이 3배로 늘고 서버 생성이 3주 지연되는 상황이 겹쳤을 때는, 3주를 만회하는 대신 Scale-out 가능한 구조를 먼저 확보하는 쪽을 택해 요구사항 개발과 배포 스크립트를 병렬화했습니다. Manifest 작성이 핵심 지연 구간이 되자 인력 투입을 기다리지 않고 직접 학습해 작성에 참여했고, 그 결과 CKA를 취득했습니다.

**결과** 추가 리소스 투입 없이 전체 이관 마일스톤 온타임 완료, 결함률 0건 / TCP 연동 아키텍처가 프로젝트 전체 표준으로 채택 / Confluence 진척 추적표로 Manifest 진행률 99.8%까지 추적

### 2. 공식 권한 없는 3자 구조에서 이해관계자 요구를 조율하고 병목을 아키텍처로 흡수

**KT ADD 고도화 · PM · 2026.05~현재**

kt(PO), ktds 개발팀, 협력사 3자 구조의 AI 미디어 에이전트 연동 프로젝트입니다. 공식 지휘 권한 없이 연동 규격과 아키텍처를 확정하고, 각 조직의 제약을 서로의 언어로 번역해 의사결정을 이끌어냅니다. GPU를 확보하지 못해 오픈소스 모델 운영이 불가능한 상황에서, 그 원인이 기술적 한계가 아니라 사업부서의 예산 미확보와 물리 장비 부족임을 구분해 PO의 의사결정 사항으로 문서화했습니다. 개발팀이 풀 수 없는 문제를 개발팀의 블로커로 남기지 않기 위한 판단이었습니다.

절차적 소통을 불편해하는 고객 특성을 고려해 대외는 대화형, 내부는 결정·리스크 레지스터로 병행 운영하는 이중 트랙 체계를 설계했고, 블로커 체류일·의사결정 리드타임·마감 명시율 지표를 직접 설계해 착수 시점부터 주간 추적했습니다.

**결과** MA 연동 규격서 확정 완료, Contents Agent 인프라 설계 완료 / 블로커 체류일 7일 이상 0건, 마감 명시율 100% 유지 / 범위·일정·리소스 트레이드오프에 오너십과 응답 기한을 붙여 kt에 반환

### 3. 지휘 권한 없는 17개사 프로세스 설계, 그리고 전사 프로세스 개선으로 확장

**KT 통신 빅데이터 플랫폼 포털 · 포털 PL · 2019.07~2020.02**

지휘 권한과 보고 라인이 없는 17개 외부 협조사가 스스로 산출물을 제출하게 만들어야 하는 문제였습니다. 생소한 국제 메타데이터 표준(DCAT)을 협조사가 바로 적용할 수 있는 형태로 번역해 작성 가이드·양식·예시·명명 규칙·기한을 하나의 패키지로 배포했고, 공통 가이드 기반 비동기 소통과 미이행 업체 개별 컨택을 2단 구조로 운영해 협조 비용을 최소화했습니다. 중도에 표준이 변경됐을 때는 확정을 기다리는 대신 임시 포맷으로 실무를 중단 없이 운영했습니다.

이 경험에서 얻은 "개별 대응을 공통 프로세스로 바꾸면 협조 비용이 준다"는 원칙은 이후 전사 ITO 사업구조혁신 TF(2024.06~2024.12)로 이어졌습니다. 현업이 관행으로 여겨 문제로 인식조차 못 하던 신규 위탁 계약 이슈를 3년치 사례로 수집·분류·패턴화해 전사 대가산정 프로세스 수립으로 연결했습니다.

**결과** 메타데이터 140건 수집, 과기부 시연 일정 내 오픈 / 롤오프 이후에도 ITO 업무량 측정 프로세스가 6개월여간 실제 실행 / 2026 ITO 단가 인상으로 연결
